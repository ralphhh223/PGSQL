# 0924_课1-2作业

开发题（6）：循环双向链表顺序搜索与 Linux PMU 统计。

## 编译与运行

在 Linux 上使用 GCC 9 或更新版本：

```bash
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic -o linked_list_perf linked_list_perf.c
./linked_list_perf --self-test
set -o pipefail
for mode in head tail miss; do
    ./linked_list_perf 10000 2000 "$mode" 2>&1
done | tee "$(date +%m%d)_1.log"
```

运行参数依次为节点数、重复搜索次数和搜索模式（头部命中、尾部命中或未命中）。正式记录时，将程序和日志放在课程指定的 `/home/assit/hk2` 中。

## 实现与计数口径

- 每个节点存放 32–512 字节的二进制载荷。节点和载荷共用一次分配，便于释放，也可改善局部性。多个链表分别持有头指针，接口没有固定的链表数量上限，规模取决于可用内存。
- 尾部追加为 O(1)。搜索从头开始，先判断长度，再用 `memcmp` 比较内容，返回第一个命中。搜索最坏遍历 O(n) 个节点，若计入每次比较的载荷长度上限 m，最坏时间为 O(nm)。没有哈希索引。
- 两组 `perf_event_open()` 分别采集指令/周期与 L1D 读取/读取未命中。建表、预热、输出和释放在统计区间之外。统计包含搜索调用与循环本身的少量开销。
- 访存次数采用 L1D 读取事件口径，覆盖只读搜索中的数据读取，不等于全部读写访问或 DRAM 访问。L1D 读取命中率 = (读取次数 − 读取未命中次数) / 读取次数。若计数器复用，数量按启用时长 / 实际运行时长缩放。同组访问和未命中使用相同采样窗口。
- 部分 CPU、虚拟机或内核策略会限制 PMU。此时相应指标显示 `N/A` 并保留错误信息。退出状态 0 表示自测通过或基准指标齐全，1 表示输入或功能错误，2 表示搜索通过但至少一项指标不可用。若遇到权限错误，由课程机管理员按本机策略开放 PMU 访问后，重跑同一命令。
